## 入口
用户发来发票台账（Excel、CSV），要在入账或报销前核一遍，或者问「这批票有没有问题」时。

别拿错：只管“已有台账表”的逐行核对；从原件建档用 e-invoice-archive，出报销单用 invoice-reimburse。

## 步骤
1. 先确认台账的列含义，尤其是金额列、税额列、价税合计列分别是哪一列，有没有合并单元格和空行。
2. 逐行核五项，每项单独出结果：
- 重复报销：发票代码 + 发票号码相同的行，保留最早一行，其余标重复；同号不同额单独标出。
- 价税勾稽：金额 + 税额 = 价税合计，容差 1 分，不符的行标出差额。
- 抬头与税号：购买方名称与本单位是否一致，纳税人识别号是否 18 位且与本主体一致。
- 开票日期：是否晚于基准日（未来票）、是否跨年、是否超出报销时限。
- 模板占位符：有没有残留的示例文字、空值、井号占位、单位写成「元」但数值带千分位的。
3. 输出三样：异常清单（行号、问题、依据、建议动作）、规范化后的台账、未执行的检查项及原因。
4. 统计口径写清：共几行、几行异常、几类问题各几条。

## 容易出错的地方
算式必须真算：先把「金额 + 税额」算出一个数，再拿这个数去比价税合计；不允许把表上的价税合计直接拄到等号右边当结果。反例：金额 200、税额 26、价税合计 300，200+26=226≠300，差 74，必须报为不符，写成「相符」就是错的。
- 台账里同一张票拆成多行（部分报销），按票号去重会误杀，要按金额合计判断。
- 金额列是文本格式带逗号，直接求和会错。
- 税额为 0 的票（免税、不征税）不是错误，别标异常。
- 抬头用了集团名、简称、旧名称，都会导致不可抵扣。
- 日期格式混用（2026/10/5 与 2026-10-05）会导致排序与比对失效。

## 怎样算办成
- 每条异常都指到具体行号，并给出依据与建议；
- 规范化台账能直接导入财务系统；
- 没做的检查项明确列出，不假装全核过。

## 什么时候停下交给用户
- 要上传到税局、发票平台或调用查验接口时，停下交给用户。
- 台账结构看不懂、关键列缺失时，停下问，不要自行推断列含义。
- 涉及补税、罚款、供应商追责的结论，只给事实与差额。
