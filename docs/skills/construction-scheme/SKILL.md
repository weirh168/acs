## 入口
用户要「施工方案 / 专项施工方案 / 施工组织设计 / 技术交底 / 方案重写 / 监理退件整改 / 专家论证方案 / 以工代赈方案」时。规则版本 R1（2026-11-20）。

**三句红线，写在最前**：
1. 第五章不到 2,300 字、或任一 5.x 缺「质量检验」三级节 → 判不合格，不许交付。
2. 目录必须由正文标题数组生成；目录与正文不一致是本链路已发生过的实际缺陷。
3. 签字、盖章、姓名、电话一律留空或写「（待填）」，**绝不代为填写或编造**。

## 步骤
1. **先分类**：`args: ["classify", "--depth", "4.8", "--formwork", "6", "--lift-kn", "80", "--scaffold", "15"]`。四门槛：基坑 ≥5 m、支模 ≥8 m、吊装 ≥100 kN、脚手架 ≥20 m；命中任一项 → 类型升为「专家论证方案」并加专项章节。缺哪项参数就问用户，不要默认。
2. **准备 project.json**（放 /workspace 下）：必须有 name/client/contractor/duration_days/segments；norms 至少 5 条带标准号；输出目录用 output_dir。人员姓名电话留空会写「（待填）」。缺字段脚本会拒绝。
3. **生成**：`args: ["new", "--project", "project.json", "--type", "道路硬化", "--out", "out"]`。支持 8 类：道路硬化 / 挡土墙 / 排水渠 / 灌溉管道 / 高位水池 / 雨季施工 / 安全文明 / 劳务管理。
4. **批量**：`args: ["batch", "--project", "project.json"]`，按 project.json 的 schemes 生成，另出 summary.md（每份的章/节/字/表/第五章字数/自检结果）。
5. **复核存量方案**：`args: ["audit", "--docx", "旧方案.docx"]`，输出章数、节数、字数、表数、第五章三段式覆盖、缺项清单与 pass。
6. 生成后**必须**把自检结果原样报给用户：章数 12、第五章字数、正文总字数、表数、9 条断言过了几条。未过就不交付。

## 容易出错的地方
- **别把「≥30000 字」写进报告**：实测成品正文 6,622–10,304 字，本脚本产 6,000–7,700 字，30,000 是文件大小被误当字数。
- 编制依据必须给「标准号 + 名称」，且核对现行有效；引用已废止规范 = 方案无效。
- 以工代赈红线：劳务报酬 ≥中央投资 40%、项目区群众 ≥80%、日工资技术工 150 / 普工 148、公示 ≥7 天；机械租赁费、材料费、管理人员工资**不得计入**劳务报酬。
- 负向清单：楼堂馆所、风雨亭、雕塑、路灯、泵站、入户围墙等一律不得出现。
- 可建设限制：道路宽 ≤4.5 m 且不能沥青、挡墙高 ≤6 m、雨污 DN ≤600、供水 DN ≤100、沟渠宽深 ≤1.0 m。
- 窄村道（<4 m）必须用小型机械（PC60、0.8 t 压路机），写 PC200 会被监理挑。
- 中文字体必须走 `w:eastAsia`，只设 `font.name` 中文不生效——脚本已处理，别自己改。
- 成品**零配图**，「八、附图」只能是文字清单；用户要求配图要另说清需人工插图。

## 怎样算办成
- 生成 docx 且 9 条断言全过；文件路径、章/节/字/表数、第五章字数都报给用户；
- 目录条目数与正文一级标题数一致（脚本同源生成）；
- 签章页存在且签署栏为空。

## 什么时候停下交给用户
- project.json 缺必填字段、或 norms 少于 5 条 → 停下要数据，不要编项目信息。
- 用户要求签字、盖章、编造人名电话 → 拒绝，只留空。
- 用户要求写「符合设计要求」「按规范执行」这类无参数表述 → 说明会被判空洞描述，要求给具体数值或按脚本给的参数写。
- 要求配图、要求 30,000 字、要求跳过自检直接交付 → 说明做不到/不合规，停下确认。
