## 入口
用户要建表格、改表格、看 Excel 里写了什么、把数据导出成 xlsx，或者贴了个 .xlsx 让你核对时。文件在 `/workspace/` 下（inbox、downloads 或用户指定路径）。

## 步骤
1. 先看有没有原文件：有就读，没有就新做。读用 `run_bundled_script`，`source` 填 `skills/office-xlsx`，`args: ["read", "inbox/a.xlsx"]`；只看某个表加 `--sheet 名称`，只取前 N 行加 `--max-rows 50`。
2. 读出来是 JSON：每个表有 name 和 rows（二维数组，按行给）。先向用户确认哪一行是表头、金额单位是什么，再动手。
3. 新建或整体重写：先写一份 spec JSON（放在 workspace 里），再调 `run_bundled_script`，`args: ["write", "spec.json", "out.xlsx"]`。
   spec 格式：`{"sheets":[{"name":"销售明细","columns":[{"width":14}],"rows":[[{"v":"日期","b":true},{"v":129.5,"fmt":"0.00"}]]}]}`。单元格可以是字符串、数字、布尔，也可以是对象：`v` 值、`b` 加粗、`fmt` 取 `0.00` 或 `date`、`f` 写公式如 `SUM(C2:C3)`。
4. 多表就多条 sheets；表名超过 31 字会被截断。列宽按内容给，别一律默认。
5. 金额保留两位小数用 `fmt: "0.00"`；日期写 `YYYY-MM-DD` 并给 `fmt: "date"`。
6. 做完把文件路径告诉用户，并说清有几个表、几行几列。

## 容易出错的地方
合计行的公式不能把自己算进去：数据在第 2–3 行、合计写在第 4 行时，要写 SUM(C2:C3)，写成 SUM(C2:C4) 就是循环引用，Excel 会报错。
- 公式只写不预算值，打开 Excel/WPS 才会算出结果；不要声称「已汇总为 889.5」，要说「已写入公式，打开后自动计算」。
- 读文件时公式单元格可能读到空，这是缓存值缺失，不是数据丢了。
- 表名不能含 `:` `\` `/` `?` `*` `[` `]`，超过 31 字会截断。
- 数字写成字符串（`"129.50"`）会导致无法求和，能写数字就写数字。
- 合并单元格、条件格式、图表、图片本脚本不支持；原表里有这些内容时，读出来会丢，要提前告诉用户。
- 一行里末尾的空单元格会被省略，读回来行长度不一致是正常的。

## 怎样算办成
- 文件生成或修改成功，路径明确；
- 表和行列数与用户要求一致；
- 金额、日期格式正确，打开后不用再手工调格式。

## 什么时候停下交给用户
- 要覆盖用户原来的表时，先说清楚会怎么改，等确认。
- 原表有图表、透视表、合并单元格等脚本处理不了的内容，停下说明会丢哪些。
- 数据量大到一次读不完（几千行以上），先问要看哪几个表、哪几列。
