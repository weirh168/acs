## 入口
用户要写报告、通知、合同草稿、会议纪要，或者发来 .docx 让你读内容、改格式、提取表格时。文件在 `/workspace/` 下。

## 步骤
1. 已有文档先读：`run_bundled_script`，`source` 填 `skills/office-docx`，`args: ["read", "inbox/a.docx"]`。返回每段的 style 与 text，以及所有表格的二维内容。
2. 要新建或重写：写一份 spec JSON，再 `args: ["write", "spec.json", "out.docx"]`。
   spec 是 blocks 数组，每块一个 type：`title` / `h1` / `h2` / `h3` / `p` / `bullet` / `numbered` / `table` / `pagebreak`。
   段落可以给整段 text，也可以给 runs 控制局部格式：`{"type":"p","runs":[{"t":"本季 ","},{"t":"12.8 万","b":true,"color":"C00000"}]}`。
   表格：`{"type":"table","header":["区域","金额"],"rows":[["华东","76000"]]}`。
3. 结构按「标题 — 小标题 — 正文 — 要点」来排，别整篇一个段落堆到底。
4. 中文正文用默认字体即可（脚本内置宋体），标题自动加粗放大。
5. 做完告诉用户路径、有几段、有没有表格。

## 容易出错的地方
- 项目符号与编号由脚本的 numbering 定义，段首不要自己再写「•」或「1.」，会重复。
- 加粗只作用在 run 上；整段加粗要把 text 拆成 runs 再给 b。
- 分页是独立一块 `{"type":"pagebreak"}`，别塞在段落文字里。
- 读回来的样式名可能是 `heading 1` 这种英文，对应文档里的「标题 1」。
- 图片、页眉页脚、脚注、目录、批注本脚本不支持，读出来会丢；原文档有就提前说明。
- 覆盖原文件前先备份或另存新名。

## 怎样算办成
- 文档生成成功、路径明确；
- 标题层级清楚、要点成列表、表格边框可见；
- 用户在 Word/WPS 里打开无需返工排版。

## 什么时候停下交给用户
- 要覆盖用户原文档时，先说明改动范围并等确认。
- 原文档含图片、页眉页脚、目录域、批注时，停下说明这些会丢。
- 涉及合同、法律条款、对外正式函件，只出草稿，注明「需人工审校」。
